Jenkins
--------
Jenkins is an open-source automation server widely used to automate the building, testing, and deployment of software projects. 
It helps developers integrate changes more easily and deliver updates more frequently by automating parts of the software development lifecycle (SDLC), especially in Continuous Integration (CI) and Continuous Delivery/Deployment (CD).

Key Features of Jenkins:
Continuous Integration & Continuous Delivery (CI/CD):
Jenkins automatically builds and tests code whenever developers push changes to the repository.
Extensible with Plugins:
Jenkins has over 1,800+ plugins for integrating with various tools (Git, Maven, Docker, Kubernetes, etc.).
Distributed Builds:
Jenkins can distribute tasks across multiple machines, speeding up builds and tests.

Pipeline Support:
Jenkins supports declarative and scripted pipelines to define end-to-end workflows in code (Jenkinsfile).

Web-based Interface:
It provides a user-friendly dashboard to monitor builds, pipelines, and logs.
Integration with Version Control:
Supports tools like Git, SVN, and Mercurial.

Use Cases:
Automating the build process after each code change
Running unit and integration tests automatically
Deploying applications to servers or cloud environments
Monitoring long-running jobs (e.g., cron jobs or scheduled tasks)

Example Workflow in Jenkins:
Developer pushes code to GitHub.
Jenkins detects the change using a webhook.
Jenkins pulls the code and runs a build script (e.g., Maven, Gradle).
Jenkins runs automated tests.
If successful, Jenkins deploys the code to staging or production.

Introduction to Apache Maven
Apache Maven is a build automation and project management tool primarily used for Java projects, though it can be used with other programming languages. It simplifies the build process (compiling code, packaging binaries, running tests, etc.) and manages dependencies and project configurations in a standardized way.
What Is Maven?
Maven helps developers:
Manage project builds
Handle dependencies
Generate documentation
Run tests
Manage project versions
Standardize project structures
Key Concepts
1. POM (Project Object Model)
The heart of every Maven project is the pom.xml file.
It defines:
Project metadata (name, version, description)
Dependencies (external libraries)
Build settings and plugins
Repositories
Project hierarchy (if using modules or parent-child structure)
Example:
<project xmlns="http://maven.apache.org/POM/4.0.0"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                           http://maven.apache.org/xsd/maven-4.0.0.xsd">
  <modelVersion>4.0.0</modelVersion>
 
   <groupId>com.example</groupId>
  <artifactId>my-app</artifactId>
  <version>1.0.0</version>
 
  <dependencies>
      <dependency>
          <groupId>junit</groupId>
          <artifactId>junit</artifactId>
          <version>4.13.2</version>
          <scope>test</scope>
      </dependency>
  </dependencies>
</project>
2. Standard Directory Structure
Maven expects a consistent project layout:
my-app/
├── pom.xml
└── src/
   ├── main/
   │   └── java/         → Application source code
   └── test/
       └── java/         → Test source code
3. Lifecycle Phases
Maven has predefined build lifecycle phases, like:
validate – Check project structure
compile – Compile source code
test – Run unit tests
package – Package code (e.g., JAR)
verify – Run integration checks
install – Install the package into local repository
deploy – Deploy to remote repository

Run using:
mvn compile
mvn test
mvn package

4. Dependency Management
Instead of downloading and managing JAR files manually, you just declare them in pom.xml, and Maven handles the rest.
5. Repositories
Local repository: On your machine (e.g., ~/.m2/repository)
Central repository: Public repository of libraries (https://search.maven.org/)
Remote repositories: Custom or private repositories (e.g., corporate Nexus/Artifactory)

Benefits of Maven
Declarative, consistent build processes
Easy dependency management
Powerful plugin system
Supports large, modular projects
Integrates well with CI/CD tools (e.g., Jenkins, GitHub Actions)
Getting Started
Install Maven:
Download from https://maven.apache.org
Unzip and set MAVEN_HOME
Add bin to your PATH
Run:
mvn -v
Create a new project:
mvn archetype:generate -DgroupId=com.example \
                     -DartifactId=my-app \
                     -DarchetypeArtifactId=maven-archetype-quickstart \
                     -DinteractiveMode=false

Build profiles
Build profiles in Maven allow you to customize the build process for different environments or scenarios — such as development, testing, production, or CI/CD.
They let you define different configurations like:
Dependencies
Plugins
Properties
JVM options
Resource filtering
Build directories
Why Use Build Profiles?
Imagine you have:
Different database settings for dev and prod
Optional dependencies or plugins that only apply in certain environments
Different JVM memory settings for test and production
Instead of manually changing pom.xml, you can define profiles to switch between configurations.
Where Can You Define Profiles?
Inside pom.xml – Most common
In ~/.m2/settings.xml – For user-specific or secure settings (e.g., credentials)
From the command line – Temporary activation


 
Example: Profile in pom.xml
<project>
 ...
 <profiles>
   <profile>
    <id>dev</id>
    <properties>
      <env>development</env>
    </properties>
    <activation>
      <activeByDefault>true</activeByDefault>
    </activation>
   </profile>
 
   <profile>
    <id>prod</id>
    <properties>
      <env>production</env>
    </properties>
   </profile>
 </profiles>
</project>
application.properties
env=prod
You can use ${env} in your config (like src/main/resources/application-${env}.properties).
Goal
Use Maven profiles to:
Build your Java project differently for development and production environments.
Change settings like a system property or resource file based on the profile.

The Project Object Model (POM) in Maven
The Project Object Model (POM) is the core of every Maven project. It's defined in a file named pom.xml, located at the root of your project.
This file describes everything about your project — structure, dependencies, plugins, build settings, versioning, and more.
What is pom.xml?
It's an XML configuration file that tells Maven:
What the project is (name, version, etc.)
What libraries it needs
How it should be built (compile, test, package)
Where to find or deploy artifacts
And more
Key Elements of a POM
Here’s a breakdown of the most important parts of pom.xml:
1. <project> (Root tag)
<project xmlns="http://maven.apache.org/POM/4.0.0"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                           https://maven.apache.org/xsd/maven-4.0.0.xsd">
   ...
</project>
2. Basic Project Coordinates
These define your project’s identity in the Maven ecosystem.
<groupId>com.example</groupId>         <!-- Usually your domain or organization -->
<artifactId>my-app</artifactId>        <!-- Unique name of the project/module -->
<version>1.0.0</version>               <!-- Project version -->


 
3. <dependencies>
Used to declare external libraries your project needs.
<dependencies>
 <dependency>
   <groupId>org.apache.commons</groupId>
  <artifactId>commons-lang3</artifactId>
  <version>3.12.0</version>
 </dependency>
</dependencies>
4. <build>
Defines build-related settings, like plugins, directories, and resource filtering.
<build>
 <plugins>
   <plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <version>3.8.1</version>
    <configuration>
      <source>1.8</source>
      <target>1.8</target>
    </configuration>
   </plugin>
 </plugins>
</build>
5. <repositories>
Specifies additional remote repositories to search for dependencies.
<repositories>
 <repository>
  <id>my-repo</id>
  <url>https://repo.mycompany.com/maven2</url>
 </repository>
</repositories>
6. <properties>
Custom variables used throughout the POM for reusability.
<properties>
<java.version>17</java.version>
</properties>
You can then use ${java.version} elsewhere in the file.
7. <profiles>
Conditional configurations for different environments or use cases (dev/test/prod).
<profiles>
 <profile>
  <id>dev</id>
   <properties>
    <env>development</env>
  </properties>
 </profile>
</profiles>

Maven Build Lifecycle
In Apache Maven, the build lifecycle is a series of phases that define the steps Maven takes to build and deploy your project.
Instead of writing custom scripts for compiling, testing, packaging, and installing your project, Maven provides standard lifecycles that handle all of that automatically.
What Is a Build Lifecycle?
A build lifecycle is a sequence of build phases, and each phase can execute one or more plugins or tasks.
When you run:
mvn package
Maven executes all phases before and including package.
The 3 Built-in Lifecycles
Lifecycle
	
Purpose


default
	
Builds the application (most used)


clean
	
Cleans up the workspace


site
	
Generates project documentation
The default Lifecycle — Most Important
This is the main lifecycle used to build your application.
Here are its key phases, in order:
Phase
	
Description


validate
	
Validates the project structure and POM


compile
	
Compiles the source code


test
	
Runs unit tests (using Surefire plugin by default)


package
	
Packages the code into a JAR, WAR, etc.


verify
	
Runs additional checks (e.g., integration tests)


install
	
Installs the package to your local repository


deploy
	
Deploys the artifact to a remote repository
 


 
Example:
mvn install
This runs:
validate → compile → test → package → verify → install
The clean Lifecycle
Used to remove build artifacts.
Phase
	
Description


pre-clean
	
Runs tasks before cleaning


clean
	
Deletes the target/ directory


post-clean
	
Tasks to do after clean
Example:
mvn clean
The site Lifecycle
Used to generate documentation and reports for the project.
Phase
	
Description


pre-site
	
Prepares the documentation


Site
	
Generates the project’s site


post-site
	
Finalizes site processing


site-deploy
	
Deploys the site to a web server
Example:
mvn site
How Does It All Work?
Each phase is associated with plugins (and goals). When you invoke a phase, Maven:
Runs all previous phases in that lifecycle
Executes configured plugins tied to that phase


 
Example for package phase:
<build>
 <plugins>
   <plugin>
    <artifactId>maven-jar-plugin</artifactId>
    <version>3.2.0</version>
    <executions>
      <execution>
        <phase>package</phase>
        <goals>
          <goal>jar</goal>
        </goals>
      </execution>
    </executions>
   </plugin>
 </plugins>
</build>
Summary of Common Lifecycle Commands
Command
	
What It Does


mvn compile
	
Compiles source code


mvn test
	
Compiles and runs tests


mvn package
	
Compiles, tests, and packages the code


mvn install
	
Installs the package to local repo


mvn deploy
	
Deploys to a remote repo (e.g., Nexus)


mvn clean
	
Deletes target/ and cleans the project


mvn site
	
Builds project documentation
